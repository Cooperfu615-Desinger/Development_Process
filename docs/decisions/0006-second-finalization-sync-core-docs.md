## 做法：先比對、再只改有差的地方

不重建整份 `SOP.html`（0004 當時的方式），改成「先逐段比對文字、只改有差的地方」。理由：比對後發現 CSS、JS、側邊欄、流程圖 SVG 都與分享版一致（差異只有分享版獨有的範例分頁與標籤文字），整份重建只會增加風險。

比對結果（以 8/26 同步後的 `core/SOP.html` 為基準）：

| 範圍 | 結果 |
|---|---|
| 流程圖 SVG、CSS、JS、側邊欄 | 與分享版一致（僅分享版獨有的範例分頁／標籤不同，屬刻意差異） |
| 開發流程圖、角色職掌、管理規範、客服、Figma | 文字一致，不需改 |
| QA／平台 Plane／遊戲 Plane 三份範例 | 實質內容一致；僅標點全形／半形、檔頭／頁尾格式不同，屬轉檔差異，**刻意不動** |
| **Plane 開立規則** | 分享版 8/27 已移除「Priority 定義」「Plane 導入時還要設定的項目」「管理規則（建議版）」三段 → 完整版同步移除；補上「使用原則」小標 |

## md 內部漂移（順手發現）

`SOP.md` 與 `SOP.html` 在 8/26 之後各自有小差異，本次一併以分享版為準對齊：
- 「管理規範」開頭那句導語（md 原本放在「角色參與矩陣」底下且少了後半句）。
- Cycle 使用原則裡的交叉引用：md 寫「本節」（錯，需求變更規則在管理規範），html 已是「管理規範」。
- 「適用範圍」第一句：md 原本寫「開發流程圖、角色職掌、管理規範…」，分享版／html 寫「需求分流、流程階段與關卡、角色分工…」。**為了三邊一致，md 改回分享版的舊用語**，但這句本身已過時（章節已合併改名），見下方待辦。

## 放棄的方案

- **整份用分享版重建 `SOP.html`（0004 的方式）**：放棄，理由如上，比對後只有少數文字差異。
- **把範例檔的標點統一成全形**：放棄。只是格式差異，改動面大（含表格、程式碼、數字），為了一致性冒著改壞內容的風險不值得。
- **直接取用 `PLATFORM_SPEC_STANDARD.md`／`GAME_SPEC_HUMAN_TEMPLATE.md` 原檔**：放棄。這些來源檔（`~/Desktop/Game_Development_Background/docs/samples/`、`~/Projects/Spec_Project/docs/templates/`）之後可能已有更新；本次要的是「對齊分享版」，所以以分享版內容為準。
- **在完整版 spec-example 檔案上動手**：放棄。`platform/examples/spec-example.md` 是 0005 保留的備查檔，不是本次範圍。
