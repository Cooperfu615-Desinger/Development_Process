# 決策紀錄 0004：把分享版累積的改動同步回原本工作檔案

- 日期：2026-08-26
- 決策者：Cooper
- 狀態：已完成

## 背景

自本專案早期某個時間點起，Cooper 下達過指示：「接下來的調整請都先以分享版 html 為主，等到全部改完後再更新回原本文件」。此後一連串大幅修改都只作用在 `docs/SOP-分享版.html`：手機版漢堡選單、多輪章節合併與刪除（需求分流併入開發流程圖、Figma狀態標記併入擴充文件、角色職責併入開發流程圖、決策紀律與開放問題清單整節刪除）、章節重新排序與編號（最終變成 1.開發流程圖 2.開發階段各角色職掌 3.管理規範 4.擴充文件 5.適用範圍）、流程階段從合併區間拆成 14 張逐步卡片、Plane 開立規則新增 Module/Cycle/Epic 三段使用原則、平台與遊戲 Plane 使用範例大幅改寫（遊戲從「七個固定跨遊戲專案」改成「單一共用專案+模組=遊戲/標籤=部門」）、全文表格欄寬調整。這些改動都沒有回寫進 `docs/core/SOP.md`、`docs/core/SOP.html` 及兩份 Plane 範例檔案，導致工作版與分享版嚴重不同步。

Cooper 確認分享版這一輪定案，詢問是否該回頭同步。

## 考慮過的選項

### 同步範圍

**選項 A：全部比照分享版同步（含手機版漢堡選單）**
- 結果：採用——Cooper 明確要求 `docs/core/SOP.html` 也加上漢堡選單，理由是希望工作版跟分享版行為一致

**選項 B：暫緩建立遊戲規格書範例獨立檔案（`docs/game/examples/spec-example.md`）**
- 分享版裡已經有完整的宙斯與黑帝斯250規格書內容（嵌在 `ex-game-spec`），可以順便拆成獨立檔案填上原本「待補」的位置
- 結果：暫緩——Cooper 選擇這次只同步其他部分，此檔案維持原狀

**選項 C：暫緩平台規格書範例**
- 分享版與工作版都還是「待補」狀態
- 結果：暫緩，維持待補

### docs/core/SOP.html 的建構方式

**選項 A：以分享版 HTML 為底稿，砍掉四份範例分頁（改成純文字/表格連結指向獨立檔案），把內嵌巨大 SVG 換回外部資產參照，其餘 CSS/JS/表格欄寬/漢堡選單原樣保留**
- 優點：確保工作版與分享版視覺、規則文字逐字一致，不會產生新的分歧
- 缺點：檔案體積仍然不小（分享版本體因為內嵌 SVG 高達 1.4MB，換回外部參照後工作版降到約 50KB）
- 結果：採用

**選項 B：另外手寫一份精簡版 HTML**
- 結果：放棄——會產生跟分享版遣詞用字不一致的風險，且工作量更大

## 已知風險與後續動作

- 這次同步是「當下快照」，如果日後又有指示「先只改分享版」，同樣的漂移狀況會再發生一次；沒有自動化機制防止兩邊再度分岔
- 章節內部有多處「見第N節」的文字交叉引用，這次同步時已逐一改成點名章節名稱（如「見『管理規範』」）而非數字，理由是數字已經被多輪重新編號證明不穩定，改用名稱可以降低未來再次重新編號時漏改的風險——但仍需注意人工維護時保持一致
