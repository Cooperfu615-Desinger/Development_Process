平台 Plane 使用範例

示範平台功能類專案的 Plane.io 結構與實際填寫方式,對應核心規範「Plane 開立規則」的通用欄位/卡片規則。平台的拓撲是單一需求工作單(父工作項)+ 5個子工作項,跟遊戲共用單一專案、用模組區分遊戲的做法不同。

結構

需求工作單（父工作項，PM 開立）
 ├─ 子工作項：規格文件      （企劃）
 ├─ 子工作項：開發          （開發組長 → 開發）
 ├─ 子工作項：測試          （測試組長 → 測試，送測後才建立／啟動）
 ├─ 子工作項：驗收          （PM + 需求方）
 └─ 子工作項：上線          （開發 + PM）

流程順序:PM 收到需求並確認 → 開立需求工作單 + 規格文件子工作項 → PM 與企劃討論確定規格 → 需求會議(PM/企劃/開發組長)→ 開發組長回報起訖時間、開立開發子工作項 → 開發實作 → 送測,開立測試子工作項,測試組長接手 → 測試 → 驗收子工作項 → 上線子工作項。

模組與史詩用法

模組對應功能版塊（長期存在），史詩對應版塊裡一個有始有終的具體功能，比照核心規範「Plane 開立規則」的 Module／Epic 使用原則。以下用內部功能規劃表的實際分類示範：

層級用途例子
Module（模組）功能版塊，長期存在、不會結束權限與管理員、會員管理、金流、首頁與總覽...
Epic（史詩）版塊裡一個有始有終的具體功能，對應內部功能規劃表的「功能群」欄位登入與帳號安全、管理員與群組、會員列表、會員詳情...
需求工作單（父工作項）史詩底下的具體功能項目，對應規劃表的「功能名稱」欄位後台登入、管理員列表、管理員群組與權限...

範例：權限與管理員模組下的「管理員與群組」史詩

Module權限與管理員
Epic管理員與群組
底下工作單[Feature][權限] 管理員列表（OPE-V1-AUTH-002）、[Feature][權限] 管理員群組與權限（OPE-V1-AUTH-003）

兩張工作單都用 Parent 掛在「管理員與群組」史詩底下，史詩本身也掛上「權限與管理員」模組；子工作單是否需要各自重複掛模組，待實際測試確認。

各子工作項對應負責人與產出

子工作項負責人產出物交給下一階段的內容
(父)需求工作單PM需求描述、來源、粗估時程區間(非正式承諾)開立規格文件子工作項
規格文件企劃規格書(流程圖/欄位定義/驗收標準/決策紀錄)需求會議討論確認後的規格版本
開發開發組長→開發起訖時間(開始/預計送測日)、工時拆解、技術方案、程式+單元測試送測時的自測結果、已知限制
測試測試組長→測試測試報告(功能/迴歸/金流專項驗證)Bug清單、驗證紀錄
驗收PM+需求方驗收紀錄、差異項目簽核狀態
上線開發+PM上線紀錄、交付文件包最終交付物清單

Plane.io 狀態對應(Backlog / Todo / In Progress / In Review / Done)

工作項BacklogTodoIn ProgressIn ReviewDone
需求工作單(父)需求剛登記,未確認PM已確認,已開子工作項任一子工作項執行中驗收中交付完成
規格文件-待企劃撰寫企劃撰寫中/PM討論中需求會議討論確認中規格拍板
開發-待開發組長排入(規格拍板後開立)開發實作中內部自測、準備送測已送測
測試-待測試組長接手(送測時開立)測試進行中Bug修復/迴歸中測試通過
驗收-待需求方驗收驗收進行中-需求方簽核通過
上線-待排上線上線作業中-上線完成,交付文件包已送出
